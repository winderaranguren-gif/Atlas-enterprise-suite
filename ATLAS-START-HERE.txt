ATLAS — START HERE
Version: 0.5.0 Private Production

PRODUCTION ACCESS
1. Open the deployed ATLAS origin or run the local Node server only for development validation.
2. Sign in with a real authorized ATLAS account.
3. ATLAS loads only organizations in which that authenticated user has an active membership.
4. There are no demo credentials, fake OTPs or browser-local production identities.

PRODUCTION DATA
- Supabase Auth provides real sessions.
- Row Level Security isolates each organization.
- CRM, finance/accounting, inventory, HR and documents use dedicated relational production tables.
- Specialized modules use the organization-scoped ATLAS production record fabric until a dedicated schema is justified.
- ATLAS Event Fabric connects module state changes.
- ATLAS Intelligence processes signals and workflows across modules.
- IndexedDB is used only as an offline operation queue; it is not the production source of truth.
- Private documents are stored in the protected atlas-documents storage bucket.

CURRENT PRODUCTION MIGRATION ORDER
Apply the existing historical migrations in timestamp order, followed by:
- supabase/migrations/202608090001_atlas_horizontal_production_fabric.sql
- supabase/migrations/202608090002_bootstrap_atlas_production_tenant.sql

The connected ATLAS Supabase project already has these production migrations applied.

IDENTITY
- Production identity surface: /cloud-auth.html
- Main application: /
- Configuration: atlas-config.js
- Browser configuration may contain only the Supabase project URL and publishable key.
- Never place service-role keys, database passwords, OAuth client secrets, payment secrets or provider credentials in browser code or GitHub.

EXTERNAL CONNECTORS
Provider-dependent integrations remain explicitly DISCONNECTED until credentials, supported hardware or jurisdiction-specific compliance are configured. ATLAS must not fake provider success.

VALIDATION
- npm run check:production-fabric
- npm run validate
- npm run build:prod

GitHub Actions is the release gate when GitHub-hosted runners are available. Do not bypass a failed or unavailable validation gate by claiming a deployment succeeded.
