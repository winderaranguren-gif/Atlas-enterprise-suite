# ATLAS Functional Reference Rebuild Rule

**Status:** canonical architecture policy  
**Applies to:** every ATLAS branch, module, product and future reference analysis.

## Rule

When an external product, website, application, workflow or service contains useful behavior, ATLAS may study and reproduce the **general capability, workflow and interaction logic** through an original ATLAS implementation.

ATLAS does not copy or import proprietary source code, private databases/APIs, protected course or media libraries, credentials, trademarks, logos, copyrighted assets, or distinctive pixel-for-pixel trade dress.

## “Same capability, ATLAS implementation” pipeline

1. **Reference intake** — record source, date, observed functions and permitted/public evidence.
2. **Functional decomposition** — describe user journey, states, controls, data objects, rules, error handling, accessibility and integrations without extracting proprietary implementation.
3. **ATLAS mapping** — map each primitive to existing ATLAS shared services before proposing a new subsystem.
4. **Original rebuild** — implement with ATLAS identity, permissions, audit, data ownership, global context, security and design system.
5. **ATLAS improvement** — improve interoperability, privacy, accessibility, multilingual behavior, failure recovery and truthful state reporting.
6. **Independent validation** — test the ATLAS implementation against its own requirements, not against copied source code.
7. **Promotion** — only a verified ATLAS implementation may be promoted to working/ripe fruit.

## Permanent prohibitions

- No copying proprietary source code or internal implementation details.
- No scraping/importing private user databases or credentials.
- No cloning protected courses, videos, music libraries or paid catalogs.
- No reuse of competitor logos, names or distinctive branded trade dress as ATLAS UI.
- No claim that a reference company endorses, partners with or powers ATLAS unless verified.
- No claim that studying a capability means ATLAS already implements it.

## Required ATLAS touch

A rebuilt function is not a cosmetic reskin. It must join the ATLAS ecosystem through shared primitives where applicable:

- one identity and permission model;
- one audit/traceability model;
- canonical documents/knowledge rather than duplicate silos;
- global language/locale/accessibility context;
- explicit system-of-record ownership;
- truthful maturity labels;
- provider/regulated boundaries when execution depends on third parties;
- original ATLAS visual language and naming.

## Maturity labels

- **REFERENCE STUDIED** — functionality observed/decomposed only.
- **ATLAS SPEC READY** — original ATLAS functional specification exists.
- **GREEN FRUIT** — implementation/foundation is incomplete or not fully validated.
- **WORKING FRUIT** — routed implementation with a real system of record/evidence exists.
- **RIPE FRUIT** — validated for its declared intended use and production boundary.

The reference itself is never evidence that ATLAS reached WORKING or RIPE status.
